PROJECT 5 · KV CACHE MANAGEMENT

先建立共同语言，再开始做 LLM Infra

这是一份给我们小组使用的最小学习清单。目标不是在开工前学完 Large Language Model，而是尽快补齐理解 LLM inference、KV Cache、PagedAttention、prefix reuse、eviction、offloading 所需要的知识。

已有基础：操作系统、计算机组成、基础编程和数学已经足够作为起点。训练细节、RLHF、LoRA、分布式训练和 CUDA kernel 暂时都不是前置知识。
01

HOW TO SELF-LEARN

怎么快速自学一个陌生系统方向

先问系统问题，不要先背术语

每遇到一个新概念，先回答四件事：它解决什么问题；旧方法为什么不够；它改变了哪一层系统；代价是什么。比如学习 KV Cache 时，先理解“为什么 autoregressive decoding 会重复计算”，再看 K、V 张量。

按“现象 → 机制 → 实现 → 论文”学习

先看图和直觉，建立运行时画面；再理解机制；之后看 vLLM 或 Hugging Face 的实现接口；最后才读系统论文。不要把论文当作第一次接触概念的教材。

只学当前问题需要的深度

能解释 prefill 和 decode 的差异，就先不用推导完整训练过程；能理解 PagedAttention 的 block/page 思路，就先不用研究 attention kernel。遇到真正的工程障碍，再沿依赖链向下补知识。

每学一个概念都留下“可解释输出”

不要只收藏链接。学习结束后，用自己的话写 5 到 10 句话，或者画一张图，解释给一个没看过材料的组员。讲不清楚的地方才是下一步需要补的地方。

推荐循环 看 20–40 分钟 关掉材料复述 画一张系统图 找一个真实实现对应 记录仍然不懂的问题
02

HOW TO READ PAPERS

系统论文不要从第一页逐字硬啃

第一遍 · 5–10 分钟

标题、摘要、Introduction、主要架构图和结果图、Conclusion。只回答：问题是什么、核心 idea 是什么、结果大概怎样、值不值得继续读。

第二遍 · 30–60 分钟

理解方法、关键设计选择、evaluation setup 和主要结果。局部公式或实现细节卡住时先做标记，不要让一个细节阻断整篇论文。

第三遍 · 按需

只有当这篇论文和我们的实现真正相关时，再追源码、假设、复杂推导、实验复现和潜在缺陷。

How to Read a Paper

先读这篇。重点是三遍法，以及第一遍快速判断论文的 Five Cs。

R2
Stanford CS197 · Reading a Paper
本科研究课程 · 约 10 分钟

把一篇论文压缩成 Problem、Prior Assumption、Insight、Technical Overview、Evaluation、Takeaway，很适合组内分享。

网页

每篇论文建议只留下这 7 项笔记

  1. Problem：它真正解决的系统问题是什么。
  2. Prior work：之前的方法为什么不够。
  3. Core insight：最关键的新观察是什么。
  4. Mechanism：系统具体改了什么。
  5. Evaluation：用什么 workload 和指标证明。
  6. Limitation：什么情况下可能没用甚至更差。
  7. Our project：它给 Project 5 哪一个可借鉴或可质疑的点。
